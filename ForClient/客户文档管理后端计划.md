# 文档管理系统设计方案

## 1. 系统概述

基于阿里云OSS的用户文档管理系统，前后端一体Web应用，支持公共文档和部门文档分类管理。

## 2. 角色定义

| 角色 | 说明 |
|---|---|
| 公共文档管理员 | 管理所有公共文档，管理所有部门，审批部门管理员注册申请 |
| 部门管理员 | 管理本部门文档，可查看公共文档 |

## 3. 权限设计

| 操作 | 公共文档管理员 | 部门管理员 |
|---|---|---|
| 上传/修改/删除公共文档 | ✅ | ❌ |
| 查看公共文档 | ✅ | ✅ |
| 上传/修改/删除本部门文档 | ✅ | ✅ |
| 查看本部门文档 | ✅ | ✅ |
| 管理部门（增删改） | ✅ | ❌ |
| 审批部门管理员注册 | ✅ | ❌ |

## 4. 文件格式

PDF、DOC、DOCX、TXT、MD

## 5. OSS路径设计

```
bucket/
├── public/           # 公共文档
├── dept-{dept_id}/   # 部门文档
└── recycle/          # 回收站（删除文件暂存，保留1个月后清理）
```

**回收站规则**：
- 删除文档时，文件从原目录移入 `recycle/`，保留原始路径信息用于溯源
- 回收站文件保留 **1个月** 后自动清理
- 管理员可在回收站页面恢复误删文件

**审计数据生命周期**：
- 审计表数据保留 **1年**，超过1年的记录自动清理删除

## 6. 数据模型

### users（用户表）
```
- id: 主键
- phone: 手机号
- role: 角色（admin/dept_admin）
- dept_id: 部门ID（部门管理员才有）
- status: 状态（pending/approved/rejected）
- created_at: 创建时间
```

### departments（部门表）
```
- id: 主键
- name: 部门名称
- created_by: 创建人
- created_at: 创建时间
```

### audit_logs（审计表）
```
- id: 主键
- user_id: 操作人
- action: 操作类型（login/upload/download/delete/approve_register/dept_create/dept_update/dept_delete）
- target: 操作对象（文件路径/部门名/用户ID等）
- ip: 操作IP
- created_at: 操作时间
```

**说明**：不单独建文档表，文件直接存储在OSS目录（`public/`、`dept-{id}/`），列表操作直接遍历OSS目录。审计表记录所有操作的完整日志。

## 7. 页面路由设计

### 认证页面
```
/login          # 登录页（手机号+验证码）
/register       # 部门管理员注册申请页
```

### 公共文档页（所有人可访问）
```
/public         # 公共文档列表（只读，支持下载）
```

### 管理员页面（仅公共文档管理员）
```
/admin/docs     # 公共文档管理（上传/删除）
/admin/depts    # 部门管理（增删改）
/admin/users    # 待审批用户列表 + 审批操作
/admin/recycle  # 回收站（查看/恢复/立即删除）
```

### 部门管理员页面（仅部门管理员）
```
/dept/docs      # 本部门文档管理（上传/删除）
```

## 8. 定时任务

| 任务 | 频率 | 说明 |
|---|---|---|
| 回收站清理 | 每天执行 | 删除 `recycle/` 下超过 **1个月** 的文件 |
| 审计记录清理 | 每天执行 | 删除 `audit_logs` 表中超过 **1年** 的记录 |

## 9. 技术选型

| 组件 | 选型 |
|---|---|
| 后端框架 | Flask（Python，自带模板渲染，前后端一体） |
| 模板引擎 | Jinja2（Flask内置） |
| 数据库 | SQLite（轻量，单文件部署） |
| 对象存储 | 阿里云OSS |
| 短信服务 | 阿里云短信 |
| 认证 | Flask-Login + Session |
