# 机器人管理后端系统 - 规划设计

## 1. 系统概述

机器人OTA管理和文件分发后端。管理员管理机器人，机器人从云端下载更新文件。文件存储在OSS对象存储桶，文件位置预定义，系统自动处理。

## 2. 角色设计

### 管理员（一个）

- **机器人管理**：注册机器人、分配 device\_id、生成/重置 update\_key、设置所属批次
- **批次管理**：创建更新批次、分配机器人、设置更新时间窗口
- **状态监控**：查看机器人在线状态、当前版本、最近更新时间

## 3. 数据模型

### 管理员表

```
- id: 主键
- 手机号/用户名
- 角色权限（admin）
```

### 机器人表

```
- id: 主键
- 业务名称
- 放置位置
- device_id: 机器人唯一标识（防盗）
- update_key: 更新密钥（加密存储）
- 型号
- 软件版本
- 批次ID
- 管理员ID
- 最后上线时间
- 最后更新时间
- 程序文件位置（可在版本中切换）
- 数据文件位置（可在版本中切换）
- 位置相关的文件位置（可在版本中切换）
```

### 批次表

```
- id: 主键
- 批次名称
- 更新时间窗口（错峰更新）
- 关联型号
- 状态（待执行/执行中/已完成）
```

## 4. 文件规则（预定义路径）

文件位置预定义，管理员不管理文件：

```
bucket/
├── {version}/program/{型号}/{版本号}/    # 程序文件
└── data/{version}/       # 数据文件
└── data/{position}       # 位置相关数据文件
```

机器人查询时，系统根据型号+版本号自动拼接路径，返回OSS临时URL。

## 5. 核心机制

### 防盗设计

- device\_id + update\_key 双重认证
- update\_key 加密存储，不直接暴露

### 错峰更新

- 机器人按批次分配不同更新时间窗口
- 避免一窝蜂同时更新

### 文件下载

- 机器人用正确的标识和key鉴权
- 查询是否有新程序文件
- 获取更新计划时间
- 下载新的程序文件和数据文件

## 6. 认证方式

手机号 + 验证码登录（阿里云短信服务）
