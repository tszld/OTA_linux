## 一、背景与目标

**背景：** 机器人需要访问阿里云百炼 LLM API，当前 API Key 硬编码在机器人本地，存在泄露风险且无法统一管理。

**目标：**
1. 机器人启动时到云端验证身份，获取可用的 API Key
2. 管理员可定期更换 API Key，防止泄露
3. API Key 避免明文保存在本地
4. 管理员可监控机器人在线状态

## 二、核心流程

```
┌─────────────────────────────────────────────────────────────┐
│                    机器人生命周期                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  首次启动          日常启动          管理员操作               │
│     │                │                │                     │
│     ▼                ▼                ▼                     │
│  采集硬件指纹    发送 device_id    查看机器人列表            │
│     │            + update_key      重置 API Key             │
│     ▼                │                │                     │
│  注册到云端          ▼                ▼                     │
│     │            验证身份          监控在线状态              │
│     ▼                │                                      │
│  获取 device_id      ▼                                      │
│  + update_key    获取 API Key                               │
│     │                │                                      │
│     └────────────────┘                                      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 2.1 首次注册流程

1. 机器人启动，采集硬件指纹（主板序列号 + MAC 等）
2. 发送硬件指纹到云端注册接口
3. 云端验证指纹唯一性，生成 `device_id` + `update_key`
4. 机器人保存 `device_id` + `update_key`（加密存储）
5. 云端记录：注册时间、IP、注册人、硬件指纹

### 2.2 日常认证流程

1. 机器人启动，读取本地 `device_id` + `update_key`
2. 发送认证请求到云端
3. 云端验证身份，返回 API Key（或标记"需刷新"）
4. 机器人使用 API Key 访问百炼 LLM

### 2.3 管理员操作流程

1. 管理员登录 ForManage 后台
2. 查看机器人列表（在线状态、最后在线时间、绑定部门）
3. 可操作：重置 API Key、更换绑定部门、禁用机器人

## 四、硬件指纹方案

### 4.1 平台适配

| 平台 | 指纹组成 | 采集方式 |
|---|---|---|
| **x86 设备**（PC/工控板） | 主板序列号 + 硬盘序列号 + MAC | `dmidecode` + `lsblk` + `ip link` |
| **ARM 嵌入式设备** | eMMC CID + MAC + 设备树型号 | `/sys/class/mmc_host/` + `cat /proc/device-tree/model` |
| **语音模组** | 模组序列号 | 模组厂商提供接口 |

### 4.2 指纹生成逻辑

```python
import hashlib

def get_hardware_fingerprint() -> str:
    """获取硬件指纹（平台自适应）"""
    platform = detect_platform()  # x86 / arm / voice_module
    
    if platform == 'x86':
        parts = [
            get_motherboard_serial(),  # dmidecode -s baseboard-serial-number
            get_disk_serial(),         # lsblk -dno serial
            get_mac_address()          # ip link show eth0
        ]
    elif platform == 'arm':
        parts = [
            get_emmc_cid(),            # /sys/class/mmc_host/mmc0/mmc0:*/cid
            get_mac_address(),
            get_device_tree_model()    # cat /proc/device-tree/model
        ]
    elif platform == 'voice_module':
        parts = [get_voice_module_serial()]  # 模组厂商接口
    
    # 拼接后生成 SHA256
    raw = ''.join(parts).encode('utf-8')
    return hashlib.sha256(raw).hexdigest()
```

## 五、API Key 管理策略

### 方案对比

| 方案 | 优点 | 缺点 | 推荐场景 |
|---|---|---|---|
| **A. 每次启动获取** | Key 不落地，最安全 | 依赖网络，启动慢 | 网络稳定环境 |
| **B. 本地缓存 + 定时刷新** | 离线可用，启动快 | Key 短暂落地（需加密） | 网络不稳定环境 |
| **C. 混合模式** | 兼顾安全与可用性 | 实现复杂 | 生产环境（推荐） |

### 推荐方案：C（混合模式）

1. **首次启动**：获取 API Key，本地加密缓存
2. **每次启动**：尝试刷新 Key，失败则用缓存
3. **管理员重置 Key**：云端 `api_key_version` +1，机器人下次请求时强制更新

### 本地加密方案

```python
from cryptography.fernet import Fernet

# 使用 device_id 派生加密密钥
key = derive_key(device_id)
cipher = Fernet(key)

# 加密存储
encrypted_key = cipher.encrypt(api_key.encode())
save_to_file(encrypted_key)
```

## 六、核心 API 设计

| 接口 | 方法 | 说明 | 认证方式 |
|---|---|---|---|
| `/api/robot/register` | POST | 首次注册 | 无（硬件指纹） |
| `/api/robot/authenticate` | POST | 日常认证 | device_id + update_key |
| `/api/robot/check-update` | GET | 检查更新 | device_id + update_key |
| `/api/robot/download` | GET | 下载文件 | device_id + update_key |

### 6.1 注册接口

```
POST /api/robot/register
Request:
{
    "hardware_fingerprint": "abc123...",
    "model": "x86",
    "dept_id": 1
}

Response:
{
    "device_id": "uuid-xxx",
    "update_key": "key-xxx"
}
```

```
POST /api/robot/authenticate
Request:
{
    "device_id": "uuid-xxx",
    "update_key": "key-xxx",
    "current_key_version": 1
}

Response:
{
    "api_key": "sk-xxx",
    "key_version": 2,
    "force_refresh": true
}
```

## 七、待讨论问题

### 问题 1：API Key 是否允许本地缓存？

- **选项 A**：不允许，每次启动必须联网获取
- **选项 B**：允许，本地加密缓存（推荐）
- **影响**：决定机器人离线时能否工作

### 问题 2：硬件指纹采集代码放哪里？

- **选项 A**：机器人端单独仓库，ForManage 只提供 API
- **选项 B**：ForManage 提供 Python SDK，机器人端集成
- **影响**：决定 ForManage 是否需要提供 SDK

### 问题 3：语音模组的设备序列号怎么获取？

- **现状**：需要确认模组厂商是否提供序列号接口
- **影响**：决定语音模组能否纳入统一管理

### 问题 4：机器人离线时能否工作？

- **选项 A**：不能，必须联网获取 API Key
- **选项 B**：能，使用本地缓存的 Key（推荐）
- **影响**：决定 API Key 管理策略

## 九、风险与注意事项

1. **硬件指纹冲突**：不同批次设备可能指纹相同，需加盐处理
2. **update_key 泄露**：需定期轮换，管理员可手动重置
3. **网络延迟**：认证接口需优化响应时间，避免阻塞机器人启动
4. **数据库安全**：update_key 和 api_key 需加密存储
